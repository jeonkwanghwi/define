# 마을 아이템 — 단어로 만든 물건을 집 안에 진열 (설계)

> 2026-09-20. 2026-06-28 회의 결정("메모가 곧 마을의 이미지")을 실제 기능으로 옮긴 것.
> 마을 v1 설계: [2026-09-20-village-v1-design.md](./2026-09-20-village-v1-design.md)

## 무엇을 만드는가

사용자가 쓴 **단어 하나를 물건 하나로 만들어** 자기 집 안에 진열한다. 남의 집에 들어가면 그 사람이 만든 물건들이 보이고, 물건 밑의 이름표로 어떤 단어인지, 눌러보면 그 사람이 그 단어를 어떻게 정의했는지 볼 수 있다.

마을 v1은 "집에 들어가면 정의 목록이 시트로 올라온다"였다. 그건 **물건을 놓을 공간이 없다** — 그래서 집 안을 실제 화면으로 만든다.

## 결정 (브레인스토밍 2026-09-20)

| 질문 | 결정 | 이유 |
|------|------|------|
| 아이템 단위 | **단어 1개 = 물건 1개** | 마을은 "단어" 서비스다. 기록마다 만들면 집이 포화되고 비용이 계속 늘어난다 |
| 만드는 방법 | **잉크를 써서 직접 만든다** | 비용이 통제되고, 잉크 소비처가 회상(30) 말고 하나 더 생긴다 |
| 다시 정의했을 때 | 물건은 **그대로 두고**, "다시 만들까요?" 제안 | 자동 재생성하면 사용자 모르게 비용이 나간다. 만든 시점에 박제되는 편이 기록답다 |
| 집 안 화면 | **방 그림 위에 물건을 올린다** | 좌우 2단 목록도 검토했으나, 마을과 같은 방식(그림+좌표)이라 파이프라인을 재사용한다 |
| 단어 표시 | 물건 밑 **이름표**, 누르면 정의 | 남의 집에서도 한눈에 읽힌다. 누르기 전엔 모르면 구경이 답답하다 |
| 자리 부족 | **페이지 넘기기**(한 판 12개) | 그림 한 장을 재사용하면서 물건이 몇 백 개가 돼도 버틴다 |
| 방 그림 | **3~4종 중 배정** | 집집마다 조금씩 다르되 생성 비용 0 |
| 내 방 진입 | **마을 중앙에 내 집**(문 앞 팻말 + 바닥 빛) | 남이 내 집에 온다는 감각이 산다. 진입로가 하나라 상태 관리도 단순 |
| 그림체 | 마을과 같은 **픽셀아트 사물** | 진열장·선반에 올려도 세계관이 안 깨진다 |
| 생성 실행 | **비동기**(만드는 중 → 완성) | 15~30초를 기다리게 하면 "느린 앱"이 된다. 기다림을 기대감으로 바꾼다 |

## 화면과 흐름

```
마을 → 집 문 앞 → [들어가기] → 실내 화면(push)
                                 ├ 방 그림 + 진열 12칸
                                 │   └ 각 칸: 물건 이미지 + 이름표(단어)
                                 ├ 물건 탭 → 정의 카드(그 단어의 최신 정의 + 만든 날짜)
                                 ├ 좌우 넘김 → 다음 진열판
                                 └ (내 집만) [새 물건 만들기]
                                       └ 아직 물건 없는 내 단어 목록 → 선택 → 잉크 차감
                                          → 그 자리에 "만드는 중" → 완성되면 물건 등장
```

- 라우트: `app/(tabs)/village/house/[userId].tsx` (마을 탭 안에서 push — 뒤로 가면 마을 그대로)
- 남의 집: 읽기 전용. "만들기" 없음.
- 내 집에서 이미 있는 물건을 누르면, **그 단어를 다시 정의한 경우에만** "다시 만들기(50잉크)"가 활성.
- 물건이 하나도 없는 집: "아직 아무것도 만들지 않았어요"(남의 집) / "첫 물건을 만들어 보세요"(내 집).

## 데이터 모델

```prisma
model VillageItem {
  id            String   @id @default(cuid())
  userId        String
  word          String                  // 단어 1개 = 물건 1개
  sourceEntryId String                  // 어떤 정의로 만들었는지(역추적 = 회의 요구사항)
  status        String                  // pending | ready | failed
  imageUrl      String?                 // S3/CloudFront URL
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  @@unique([userId, word])
}
```

- `User.roomVariant Int @default(1)` — 방 그림 1~4. 가입 시 배정(기존 유저는 id 해시로 채움).
- **역추적**: `sourceEntryId`로 "이 물건은 어떤 글에서 나왔나"를 항상 되짚을 수 있다(2026-06-28 회의의 "아이템 보기" 요구).
- 다시 만들기는 **같은 레코드의 이미지를 교체**하고 `sourceEntryId`를 새 정의로 갱신한다(물건이 두 개가 되지 않는다).

## API

```
POST /api/village/items            { word }         (JwtAuthGuard)
  → 잉크 차감 → pending 레코드 생성 → 응답 → 백그라운드 생성
  400 단어 없음 / 그 단어의 정의가 없음
  402 잉크 부족
  409 이미 그 단어의 물건이 있음

GET  /api/village/items?userId=<id>                 (JwtAuthGuard)
  → { roomVariant, items: [{ id, word, status, imageUrl, definition, savedAt }] }
  정의는 그 단어의 **최신** 정의를 같이 내려준다(실내에서 바로 보여주려고)

POST /api/village/items/:id/regenerate              (JwtAuthGuard)
  → 본인 것만. 그 단어를 다시 정의했을 때만 허용(아니면 409)
  → 잉크 차감 → status=pending → 백그라운드 생성 → 이미지 교체
```

마을 이웃 API 변경: **중앙 맵 슬롯 9 → 8** (한 칸은 내 집). `TOTAL_SLOTS`가 자동으로 따라가므로 데이터만 고치면 된다.

## 생성 파이프라인

정의 글은 한국어에 추상적이라 이미지 모델에 그대로 넣으면 결과가 나쁘다. **두 단계**로 간다.

1. **프롬프트 변환** (`gpt-4.1-mini`, 회상과 같은 키)
   - 입력: 단어 + 그 정의 글
   - 출력: **사물 하나**를 묘사하는 짧은 영어 구절 (예: "행복 / 특별한 일이 없는데도 마음이 가라앉는 평일 저녁" → `a small warm desk lamp beside a closed notebook`)
   - 제약: 사람·얼굴·글자 금지, 장면이 아니라 **물건 하나**, 15단어 이내
2. **이미지 생성 → 투명 PNG → S3**
   - 스타일 고정 문구(코드 상수): `16-bit pixel art, single object, centered, flat magenta (#FF00FF) background, muted warm palette, soft shading, no text, no people`
   - 마젠타 배경을 키잉해 투명 PNG로(아바타 추출에 쓴 방식 재사용)
   - S3 업로드 → CloudFront URL을 `imageUrl`에 저장
3. **실패 처리**: 모더레이션 거부·생성 실패·업로드 실패 → `status=failed` + **잉크 전액 환불**. 실내에서는 "만들지 못했어요. 잉크는 돌려드렸어요"로 표시하고 다시 시도 가능.

비용: 장당 대략 15~30원(이미지) + 프롬프트 변환 몇 원. 사용자당 단어 수만큼이라 상한이 있다.

## 잉크 정책

| 행동 | 잉크 |
|------|------|
| 물건 만들기 | **50** |
| 다시 만들기 | **50** |
| 생성 실패 | 전액 환불 |

출석이 하루 +10이므로 닷새치. 회상 대화(30)보다 비싸게 둔 건 결과물이 영구적으로 남기 때문이다. 숫자는 운영하며 조정한다.

## 실내 그림 요구사항

- 3~4장. 세로 2:3(마을 배경과 같은 848×1264).
- **선반·진열대가 비어 있어야 한다** — 물건은 우리가 얹는다.
- 진열 자리 12칸이 눈으로 구분돼야 한다(선반 3~4단 × 3~4칸).
- 사람·글자 없음. 마을과 같은 픽셀아트, 가라앉은 따뜻한 톤.
- 좌표는 마을과 같은 방식으로 그림을 보고 찍는다(`village-rooms.ts`).

## 검증

1. **서버 curl**: 잉크 부족 402 / 중복 단어 409 / 남의 것 재생성 403 / 정의 없는 단어 400 / pending→ready 전이 / 실패 시 잉크 환불(잔액 비교).
2. **파이프라인**: 실제로 3개 생성해 **눈으로 스타일 확인**. 여기서 프롬프트를 튜닝한다(이 단계를 건너뛰면 품질을 모른다).
3. **실내 화면**: 좌표 찍고 브라우저에서 — 물건이 선반 위에 놓이는지, 이름표가 겹치지 않는지, 페이지 넘김, 남의 집에서 만들기 버튼이 없는지.
4. **마을 회귀**: `scripts/check-village.mjs` — 내 집 슬롯이 이웃 배정에서 빠졌는지, 나머지가 여전히 전부 도달 가능한지.

## 범위 밖 (v2)

- 물건 위치를 사용자가 옮기기(꾸미기)
- 방 그림도 사용자 기록으로 생성
- 건물 설치 시간(잉크로 단축) — 2026-06-15 회의 항목
- 마이페이지 "아이템 보기" 별도 진입로(지금은 마을 내 집 하나로 충분)
- 물건 품질이 마음에 안 들 때 무료 재생성 1회 같은 완화책

## 리스크

- **이미지 품질 편차**: 잉크를 쓴 결과가 기대와 다를 수 있다. 프롬프트 튜닝으로 줄이되, 완화책(무료 1회 등)은 실제 반응을 보고 정한다.
- **생성 지연**: 비동기라 화면은 안 막히지만, 완성까지 30초 넘게 걸리면 "만드는 중"이 오래 남는다. 실내 재진입 때 갱신되게 한다(폴링은 5초 간격, 화면 벗어나면 중단).
- **S3 비용·용량**: 장당 수십 KB 수준이라 미미하지만, 실패한 생성물이 쌓이지 않게 업로드는 성공한 것만 한다.
